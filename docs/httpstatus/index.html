码含义一句话判断
200成功一切正常。

最容易搞混的几组Confusing pairs

401 还是 403？

401 Unauthorized：你没证明你是谁 —— 没带 token、token 过期。正确做法是返回 WWW-Authenticate 头，引导重新认证。
403 Forbidden：服务器知道你是谁，但你没权限。此时重新登录也没用。
记忆法：401 = 没登录，403 = 登录了但不让进。

301 / 302 / 303 / 307 / 308 怎么选

码是否永久是否保持原方法典型用途
301永久历史上常被改成 GET域名迁移、http→https、去掉 www
302临时历史上常被改成 GET临时跳转、A/B 测试
303临时强制改成 GETPOST 提交后跳转到结果页（PRG 模式）
307临时保持需要保住 POST body 的临时跳转
308永久保持需要保住 POST body 的永久跳转
一句话表单 POST 想跳转就用 303；接口需要保方法用 307/308；普通页面迁移用 301。

502 还是 504？

502 Bad Gateway：网关拿到了上游的无效响应 —— 上游进程挂了、端口没监听、返回了非 HTTP 内容。
504 Gateway Timeout：网关等不到上游响应就超时了 —— 上游还活着，只是慢。
排查方向：502 查上游进程和端口（ss -ltnp、日志有没有启动失败）；504 查上游耗时（慢 SQL、下游依赖卡住）和网关超时配置（proxy_read_timeout）。

304 为什么没有响应体

304 是协商缓存命中：浏览器带着 If-None-Match / If-Modified-Since 来问，服务端说「没变，用你本地的」。所以响应必须没有 body，只有头。给 304 塞 body 会导致部分客户端解析异常。

418 能用在生产吗

能 —— 它是一个合法注册的状态码，很多站点用它拦截特定爬虫（返回 418 而不是 403，避免被当成权限错误）。但别用它表示正常的业务失败。

状态码分类速记Class semantics

  • 1xx：还在协商，不是最终结果。
  • 2xx：成功。注意 204 没有 body，别在里面读 JSON。
  • 3xx：需要再走一步。客户端要能跟随跳转，但 API 调用通常应关闭自动跟随以便观测。
  • 4xx：客户端的问题。同一个请求重发不会有不同结果，别做无脑重试。
  • 5xx：服务端的问题。可重试，但要带退避，否则放大故障。
