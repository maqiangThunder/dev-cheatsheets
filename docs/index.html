为什么是「速查」而不是「工具」Why a reference, not a tool

查表是线性的：知道要找什么，只需要快速定位。这类场景下，一页纯静态 HTML 比任何需要加载、需要点选、需要联网调接口的工具都更快 —— 打开即到，Ctrl+F 就能搜。

但有些问题查表解决不了。比如「这条 cron 下次什么时候跑」不是查出来的，是算出来的；「这段 Base64 解出来是什么」也不是查出来的。这些交给 util123.top 上的在线工具。

两手准备这里负责「记住写法」，工具站负责「验证结果」。速查页底部的按钮会直接跳到对应工具，不用自己找。

数据来源与维护Sources

  • ASCII 码表依据 ANSI X3.4-1968 / ISO 646 标准字符集整理。
  • HTTP 状态码依据 IANA HTTP Status Code Registry 与 RFC 9110 整理。
  • Cron 语法以 Vixie Cron 实现为基准 —— 这也是 Linux 发行版和大多数在线 Cron 服务实际使用的方言。
